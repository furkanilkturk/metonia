# Work space

Own company and project operating knowledge. Start in the most specific company
or project directory available. Read [[Work]] first; then read the nearest
`Company.md` and `Project.md` before proposing an operational or code-related
change.

## Boundaries

- Company facts live in `Companies/<Company>/Company.md`; do not repeat them in
  this guide or each project.
- Project facts live in `Projects/<Project>/Project.md` and inherit their
  parent company context.
- `project-learning` and `project-planning` may be used only when installed
  under `Work/.agents/skills/`.
- Do not load Learning or Studio/Video context for ordinary coding work.
- Do not record secrets, personal performance data, or restricted incident
  details. Link to an authorized system of record instead.

For a policy, architecture, or cross-project write, show the target, evidence,
owner, and expected effect before editing. A coding task may update project
knowledge only when the user asks for it or approves the proposed write.
Runtime execution plans remain in the repository or Pi session. Save a plan to
Obsidian only when its outcome, decisions, milestones, and review triggers are
intentionally durable.
